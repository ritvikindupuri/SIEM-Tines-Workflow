# Elastic Security SIEM & Automated Incident Response (Elastic + Tines)

A compact, production-safe demo of a **real-time detection → SOAR triage → email alerting** pipeline.  
It ingests Windows security events with **Elastic Agent (Defend)**, detects **admin-privileged logons** (Win Event **4672**), fires a webhook into **Tines**, auto-summarizes the incident with AI, and notifies analysts by email.



---

## ✨ Highlights

- **End-to-end pipeline:** Windows VM → Elastic Agent → Elastic Security (SIEM/EDR) → Tines SOAR → Email.
- **Detections that matter:** Custom rule for **event.code / winlog.event_id = 4672** (“Special privileges assigned to new logon”) to flag admin-level sessions.
- **Automated triage:** Tines story receives the alert, summarizes key fields, and sends formatted email notifications.
- **Dashboards:** Logon activity visuals (admin vs. non-admin, RDP, logon type, timelines).
- **Scale-minded:** Alert volume control (severity/risk score/thresholds) to prevent fatigue and keep demo safe.

## ✅ Quick Start (15–30 min)

### Prerequisites
- Elastic Stack 8.x (Elastic Cloud or local) with **Elastic Security**.
- A **Windows 10/11 VM** (local, lab, or cloud) with admin access.
- **Elastic Agent** installed on Windows VM (policy includes **Elastic Defend** + Windows Event Log).
- **Tines** tenant (free trial is fine) and an **email** integration (SMTP/Gmail, etc.).


4) Create the detection rule (manual path)
Kibana → Security → Rules → Create new rule → Custom query

Index patterns: logs-*-*

KQL query:

(event.code: 4672 OR winlog.event_id: 4672) AND host.os.type: "windows"
Severity: Low

Risk Score: 21

Schedule: Every 5 minutes (or as desired)

Max alerts per execution: 100

Actions: (Add a Webhook; we’ll wire this to Tines below.)

Tip: If your Windows Security events aren’t visible yet, enable Windows Event Logs integration in your Agent policy and confirm events in Discover with event.code: 4672 OR winlog.event_id: 4672.

5) Create the Tines Story
Import tines/story.json or build these actions:

Receive Alert (Webhook)

Method: POST

URL: (auto-generated by Tines)

Body: Raw JSON from Kibana Rule Action

Summarize (AI Action)

Prompt reads key fields such as @timestamp, host.name, user.name, event.code, event.action, source.ip, process.name, message.

Output: Short incident summary + recommended next steps.

Notify (Email Action)

To: SOC list or your email

Subject: [Elastic SIEM] Admin Logon Detected (4672) - {{host.name}}

Body: Include summarized text + raw field table for triage.

Copy the Webhook URL into your Kibana Rule’s Action → Webhook connector.

🔎 Detection Logic & Rationale
Windows Event 4672 = Special privileges assigned to new logon.
In practice, this indicates a privileged token/logon (e.g., Administrators, Local System).

We filter by host.os.type: "windows" to avoid noisy non-Windows indices.

Alert tuning options:

Add conditions like NOT user.name: "Administrator" to focus on non-standard admins.

Add source.ip allowlist to ignore known management jump boxes.

Raise severity/risk if used outside of office hours or from unusual geos.

🤖 Tines Story (Concept)
Webhook → AI Summarize → Email

Input fields: @timestamp, host.name, user.name, event.code, event.action, source.ip, winlog.logon.id, process.name, message.

AI prompt goal: Produce concise context + next steps (verify user, source IP reputation, check lateral movement, review processes/services at time of logon).

Email body: Human-readable summary + raw JSON table.

You can harden delivery via SPF/DKIM/DMARC and route to a shared SOC inbox or ticketing webhook.

🧪 Validation & Results

Scales with thresholds to avoid alert storms; useful for SOC practice and demo environments.

🔐 Safety & Ethics
Lab-only; never exfiltrate or monitor without authorization.

Avoid alert fatigue—set thresholds and filters.

Treat emails as sensitive; avoid sending full payloads outside controlled domains.

🧰 Troubleshooting
No events: Check Elastic Agent policy (Windows Event Logs + Elastic Defend); confirm logs-*-* indices in Discover.

Rule never fires: Expand the time range; lower thresholds; confirm event.code: 4672 OR winlog.event_id: 4672.

Webhook fails: Verify Kibana connector can reach Tines (egress rules, proxy, TLS).

No email: Check Tines email connector credentials, spam folder, and rate limits.

📈 What to Extend Next
Add secondary detections (e.g., 4624 Type 10 for RDP, 4769/4768 for Kerberos activity).

Enrich with GeoIP, asset tags, or identity context.

Auto-open tickets (Jira/ServiceNow) from Tines.

Add containment action stubs (e.g., isolate host via Elastic Defend—demo only).
